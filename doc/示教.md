## 示教 

描述如何使用示教工具新增一个动作，新增的动作如何更新到平台上，如果涉及到g1\_base的编译要进行说明

**g1_teach_v2 动作制作说明**

`g1_teach_v2` 是用于宇树 G1 上肢动作录制、姿态保存、动作编排和回放的工具。项目把动作资源统一放在 `g1_teach_v2/movement/` 下，最终交付时通常只需要打包这个 `movement` 文件夹。

目录约定：

```latex
g1_teach_v2/
  movement/
    motions/       连续动作轨迹，.jsonl
    snapshots/     单帧关键姿态，.json
    scripts/       动作编排脚本，.json
    def_motion.json 动作入口清单
```

**新增动作流程**

1. 录制连续动作 `motion`

适合挥手、舞蹈、打鼓、演讲手势等连续轨迹。

```bash
python -m g1_teach_v2 record-motion --mode teach_upper --out g1_teach_v2/movement/motions/my_action.jsonl
```

常用模式：

```latex
teach_upper      双臂/上肢示教录制，最常用
right_hold_left  保持左臂，主要拖动右臂
raw              仅采样当前状态，不主动控制
lock_forearm     录制时限制部分手腕轴
```

如果动作需要对齐音乐，可以录制时播放音频：

```bash
python -m g1_teach_v2 record-motion --mode teach_upper --out g1_teach_v2/movement/motions/drum.jsonl --music g1_teach_v2/music/haorizi.wav --music-backend g1
```

2. 捕获关键姿态 `snapshot`

适合保存“默认姿态”“介绍姿态”“指向姿态”“准备姿态”等可复用定格动作。

```bash
python -m g1_teach_v2 capture-snapshot --out g1_teach_v2/movement/snapshots/my_pose.json
```

执行后进入交互式拖动流程：工具接管手臂，进入轻松拖拽状态，手动摆到目标姿态后按 `ENTER` 保存。

3. 单独验证资源

验证 motion：

```bash
python -m g1_teach_v2 play-motion --path g1_teach_v2/movement/motions/my_action.jsonl --dry-run
python -m g1_teach_v2 play-motion --path g1_teach_v2/movement/motions/my_action.jsonl
```

验证 snapshot：

```bash
python -m g1_teach_v2 goto-snapshot --path g1_teach_v2/movement/snapshots/my_pose.json --dry-run
python -m g1_teach_v2 goto-snapshot --path g1_teach_v2/movement/snapshots/my_pose.json --duration 1.5
```

4. 编写动作脚本 `script`

脚本用于把 snapshot、motion、hold、hand、audio 等步骤串起来。脚本建议放在：

```latex
g1_teach_v2/movement/scripts/my_action.json
```

脚本放在 `movement/scripts/` 下时，内部路径可以写成相对 `movement/` 的短路径，例如 `snapshots/my_pose.json`、`motions/my_action.jsonl`。

示例：

```json
{
  "kind": "script",
  "version": 1,
  "defaults": {
    "profile": "upper_playback",
    "snapshot_duration": 1.5,
    "motion_speed": 1.0,
    "motion_interpolation": "cubic"
  },
  "steps": [
    {
      "type": "snapshot",
      "path": "snapshots/my_pose.json",
      "duration": 1.5
    },
    {
      "type": "hold",
      "duration": 0.8
    },
    {
      "type": "motion",
      "path": "motions/my_action.jsonl",
      "speed": 1.0
    },
    {
      "type": "snapshot",
      "path": "snapshots/default.json",
      "duration": 1.5
    }
  ]
}
```

运行脚本：

```bash
python -m g1_teach_v2 run-script --path g1_teach_v2/movement/scripts/my_action.json --dry-run
python -m g1_teach_v2 run-script --path g1_teach_v2/movement/scripts/my_action.json
```

5. 更新动作入口清单

如果动作需要被外部系统按名称发现或调用，需要在 `movement/def_motion.md` 中新增一项，指向脚本路径：

```json
{
  "actionName": "scripts/my_action.json",
  "comment": "我的新动作说明"
}
```

通常新增到 `type = action_name` 的分组里。`actionName` 建议统一写 `scripts/xxx.json`，不要写绝对路径。

6. 打包交付

确认新增文件都在 `movement/` 下：

```latex
movement/
  motions/my_action.jsonl
  snapshots/my_pose.json
  scripts/my_action.json
  def_motion.json
```

linux 打包示例：

```powershell
zip -r movement.zip g1_teach_v2\movement
```

接收方解压后保持目录结构不变，脚本里的相对路径才能正常解析。

**推荐规范**

- 一个动作文件只表达一个清晰动作含义。
- 强语义姿态后加 `hold`，避免动作马上切走。
- 复杂动作优先拆成多个 snapshot/motion，再用 script 编排。
- 新脚本上机器人前先执行 `--dry-run`。
- 每个完整脚本最后建议回到 `default` 或安全姿态。
- 交付时只打包 `movement/`，不要打包 `__pycache__` 或临时测试文件。
